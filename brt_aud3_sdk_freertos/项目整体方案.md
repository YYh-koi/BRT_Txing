# 蓝牙仪表业务逻辑梳理

## 整体架构

**仪表 ↔ 手机**

- 信息 / 控制链路：AT+profile（SDP 服务，SPP 串口）
- 音频链路：手机 ↔ 蓝牙耳机 / 蓝牙音响

> 两个独立通道：
>
> 1. SPP：用于指令交互、仪表控制（AT 命令）
> 2. 蓝牙音频（A2DP / HFP）：通话、音乐音频流

------

## 1. AT+profile 配置

```
AT+profile = 取消 A2DP sink 与 SPP service
```

- `A2DP sink`：A2DP 接收端（音响 / 耳机角色，接收手机音乐）
- SPP service：蓝牙串口服务，用来收发 AT 指令做控制交互

> 作用：关闭 A2DP 接收服务，**只保留 HFP**（通话协议）

## 2. 手机连接行为

> 手机搜索连接时，**只找到 HFP**，不建立 A2DP 音乐通道

- 现象：手机连上仪表蓝牙后，**不会自动把音乐输出到仪表**；仅支持通话音频。

## 3. AT+AVRCPCONN 主动建连逻辑

```
AT+AVRCPCONN → 主动连接手机的AVRCP
```

- AVRCP：蓝牙音频遥控协议（切歌、暂停、音量）
- 关键点：**此时 A2DP 并没有建立连接**

> 仪表主动发起 AVRCP 控制通道，但 A2DP 音频流通道还没通；AVRCP 是控制通道，A2DP 才是音乐数据流通道。

## 4. 协议分工（HID / HFP）

| 协议 | 用途         |
| ---- | ------------ |
| HID  | 控制蓝牙音乐 |
| HFP  | 控制蓝牙电话 |

## 完整流程时序

1. 仪表执行 `AT+profile`，关闭 A2DP Sink，保留 HFP。

2. 手机扫描仪表蓝牙，只能发现 HFP 服务，完成 HFP 连接。

   -  通话功能可用（HFP）
   -  此时 A2DP 音乐通道未建立，手机音乐不会走仪表蓝牙

3. 仪表下发 

   ```
   AT+AVRCPCONN
   ```

   ，主动和手机建立 AVRCP 遥控通道。

   - 可以通过 AVRCP/HID 发送播放 / 暂停、切歌指令控制手机音乐播放器
   -  **注意：仅仅是遥控指令，音乐音频流（A2DP）并没有传到仪表**

4. 若需要播放音乐到仪表蓝牙： 需要**手机侧主动发起 A2DP 连接**，建立 A2DP 音频链路，音乐音频才会输出到仪表蓝牙。

------

## 核心要点总结

> HFP = 电话通话音频；A2DP = 音乐音频；AVRCP = 音乐遥控器。

1. 用 `AT+profile` 关闭 A2DP Sink 之后，**手机不会自动连上 A2DP**。
2. `AT+AVRCPCONN` 只是建立遥控通道，**不等于 A2DP 音频通道建立**。
3. 仪表可以远程控制手机音乐播放（AVRCP/HID），但是音乐声音不会从仪表蓝牙出来；只有通话声音走 HFP。
4. HID 负责音乐按键控制，HFP 负责电话通话控制。

------

## 业务场景理解

仪表蓝牙只做两件事：

-  HFP：接打电话，通话音频走仪表蓝牙
-  AVRCP/HID：远程控制手机播放器（切歌、暂停），**但是音乐声音不从仪表蓝牙输出**，音乐仍然在手机 / 蓝牙耳机播放。
